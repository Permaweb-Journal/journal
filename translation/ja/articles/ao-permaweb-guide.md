## I. はじめに

Permaweb は、Arweave 上に構築された永続的で分散化された Web です。従来の Web の元の構想は、人類の知識のアクセス可能なリポジトリを作ることでした。これは大部分で成功していますが、重要な欠陥が残っています：Web には永続性がありません。文書がサーバーから削除されると、集合的知識ベースから失われます。同様に、かつて Web 上で動作していたアプリケーションは、開発者やメンテナーがそれらを変更または削除すると、アクセス不可能になります。

Permaweb は、すべてのデータ、アプリケーション、相互作用が永続的に利用可能であることを保証することで、これを解決します。しかし、Web の完全に分散化された代替手段を作るためには、永続的ストレージだけでは十分ではありません。中央集権的サーバーに依存することなくアプリケーションが実行できるスケーラブルでトラストレスな計算レイヤーが必要です。ここで AO が登場します。

## II. AO とは何か？

![AO](/static/images/ao-site.png)

AO は、安全でスケーラブルなコンピューティングパワーを提供するよう設計された「ハイパー並列コンピュータ」です。これは、ブロックチェーン技術の信頼性と従来のクラウドサービスの効率性とスピードを組み合わせます。開発者が中央集権的インフラを信頼することなくアプリケーションをデプロイし、計算を実行できる分散クラウドコンピューティングプラットフォームと考えてください。AO は、シンプルなスクリプトから複雑で高性能なアプリケーションまで、あらゆるスケールでパーミッションレスなオンチェーン実行を可能にします。

多くの場合スケーラビリティの制限と高コストに苦しむ従来のブロックチェーンベースのスマートコントラクトプラットフォームとは異なり、AO は膨大な量の並列処理を処理するよう設計されています。これにより、次世代の分散アプリケーション（dApps）にとって不可欠な構成要素となります。

## III. Permaweb とは何か？

![HyperBeam](/static/images/permaweb.png)

Permaweb は Arweave 上に構築された分散的で永続的な Web です。中央集権的サーバーに依存しないアプリケーションの構築と実行のための完全なスタックを提供します。Permaweb の主要コンポーネントには以下が含まれます：

- **[Arweave](arweave.md)**: 分散的で持続可能なエンダウメントモデルを通じてデータ複製と可用性を確保するストレージレイヤー。
- **[Gateways](gateways.md)**: 多様なビジネスモデルとインセンティブを持つコンテンツ配信サーバー（例：arweave.net、ar.io、g8way.io、aoweave.tech）。
- **[GraphQL](https://cookbook.arweave.net/guides/querying-arweave/queryingArweave.html)**: Gateways によって提供されるクエリシステムで、ネットワークのデータとのシームレスな相互作用を可能にします。開発者は GraphQL を使用して、従来の Web アプリケーションのように、ユーザーによる投稿を検索したり、タグやタイムスタンプでデータをフィルタリングしたりできます。
- **[AO](ao.md)**: 分散アプリケーションと Process のための統一環境を提供するハイパー並列計算レイヤー。

コアコンポーネントを超えて、Arweave の堅牢なデータレイク上に構築されたオープンプロトコルがあり、お互いのデータをシームレスに活用し構築できる合成可能なアプリケーションを可能にします。

オープンプロトコルとフレームワークには以下が含まれます：

- **[Stamps](https://stamps.arweave.net/#/en/main)**: Permaweb 上のコンテンツのための汎用「いいね」ボタン。
- **[Vouch](vouch.md)**: 分散的人間性証明システム。
- **[Zones](zones.md):** 合成可能なユーザープロファイルとデジタルエンティティフレームワーク。
- **[Universal Content Marketplace (UCM)](ucm.md)**: Permaweb 上でデジタルアセットを取引するための分散オーダーブック。
- **[Universal Data License (UDL)](udl.md)**: Permaweb データの任意の部分に添付できるプログラマブルコンテンツライセンシングフレームワーク。

Permaweb についてはもっと[こちら](permaweb.md)で学べます。

## IV. AO は Permaweb にどのように適合するか？

AO は、スケールでの分散的オンチェーン計算を Permaweb にもたらします。Arweave がデータの永続性を確保する一方で、AO はアプリケーションが中央集権的サービスに依存することなくデータを処理・計算できるようにします。AO を CPU、Arweave を Permaweb コンピュータを構成するハードドライブと考えてください。AO は、以下を含む Permaweb アプリケーションのための幅広い新しい可能性を解放します：

- **動的 dApps**: DeFi、ゲーミング、ソーシャルメディアなど、リアルタイムまたはインタラクティブ要素を必要とするアプリケーション。
- **分散 AI**: 中央集権的制御なしに単一のスマートコントラクト内で AI モデルの訓練と実行。
- **自動化 Process**: Permaweb データと並行して相互作用できるスマートコントラクトとワークフローのトラストレス実行。

AO を活用することで、開発者は永続的であるだけでなく、高度にスケーラブルで自律的なアプリケーションを構築できます。

## V. 先を見据えて、Permaweb の次は何か？

![HyperBeam](/static/images/hyperbeam.png)

### AO-Core & HyperBeam

Permaweb アプリケーションは 2024 年 2 月以来 AO legacynet 上で実行されており、開発者にこの新しいプログラミング環境での実験機会を与えています。しかし、任意のテストネットで期待されるように課題が現れました。最も顕著なのは、ユーザーとアプリケーションからの過剰な Message traffic によるコンピュートユニット（CU）での混雑です。Message の送信が無料だと、それは悪用され、非効率性につながる可能性があります。

AO がメインネット上にある今、[AO-Core](https://mirror.xyz/0x1EE4bE8670E8Bd7E9E2E366F530467030BE4C840/ot6Tu0GduY4_kKhoVw9rNPLOPix8DS_Z_3tBPhCK_v0)は単一のアーキテクチャを強制することなく様々な計算モデルを実行するための柔軟なフレームワークを提供します。さらに、AO-Core プロトコルの Erlang ベースのノード実装である[HyperBeam](https://github.com/permaweb/HyperBEAM)が現在稼働しています。ノードオペレーターは HyperBeam を使用してネットワークに計算サービスを提供し、AO メインネット上のアプリケーションは Message を送信するためにガス手数料が必要になります。この変更により、より多くのノードオペレーターがオンラインになるにつれて、ネットワークの信頼性が向上し、システムがさらに分散化されます。

### Permaweb Index

アプリケーション層では、[Permaweb Index](permaweb-index.md)が稼働しており、フェアローンチ UI が間もなくローンチされます。Permaweb Index は、ユーザーが PI トークンと引き換えに Permaweb プロジェクトに AO 収益を割り当てることができる分散資金調達メカニズムです。従来の VC 資金調達や Token presale とは異なり、このモデルは一回限りの投資ではなく継続的なコミュニティサポートを確保します。

## VI. 結論

Arweave は、デジタル知識が決して失われないことを保証し、データの保存とアクセス方法について全く新しい理解を提供します。しかし、分散 Web のビジョンを完全に実現するためには、ストレージレイヤーと同じくらい永続的でトラストレスな計算が必要です。AO は、スケーラブルなオンチェーン実行を提供することで、新世代の分散アプリケーションを可能にし、この役割を果たします。

Permaweb エコシステムが成長するにつれて、AO は中央集権的インフラに依存することなく、アプリケーションが効率的かつ安全に実行できることを保証する重要な役割を果たし続けます。AO と Arweave は共に、よりオープンで透明で回復力のあるインターネットの基盤を築いています。
